# 戶外天空與雲隙光（補充）

整理自 [MengTo/Skills](https://github.com/MengTo/Skills) 的 `3d-sky-background`、`3d-sky-rays`（MIT License, Copyright (c) 2026 Meng To），用自己的話改寫。
**這份筆記的內容還沒在本 plugin 的範例裡實測過**；本 skill 主檔的數值才是量過的。

本 skill 原本是從室內看窗外。下面補的是兩種情況：鏡頭在戶外自由移動，以及要做從屋簷、樹葉縫隙透出來的光束。

## 1. 鏡頭在戶外移動時的天空

- **三件事分開處理**：看得到的天空、反射與環境光（PMREM）、會投影的太陽光。只有背景圖不會照亮 PBR 物件，PMREM 也不會產生有陰影的太陽。本 skill 的 `skyDome`、`skyEnvironment`、`skyLights` 正好對應這三件。
- **天空球跟著鏡頭平移、不跟著旋轉**：每幀把天空球的位置設成鏡頭位置，關掉 depthWrite 與 fog，半徑要在鏡頭 near 與 far 之間。不跟著平移，走遠了就會看到天空球的邊界或視差。
- **地平線以下**：下半球的顏色要接得上地面的霧化顏色，不要留一條硬邊。
- **太陽方向只有一個來源**：太陽圓盤、光暈、方向光、雲隙光都用同一個指向太陽的單位向量。光暈和圓盤是兩個分開的項，不要做成一大團白色。

## 2. 用全景圖時

- 真正的 equirectangular 是水平 360°、垂直 180°。旋轉貼圖讓照片裡的太陽對上場景的太陽，並檢查接縫與天頂。
- 一般的寬幅風景照只涵蓋一部分角度，要記下它涵蓋的角度和地平線位置，不要硬拉成整顆球。
- 自己寫 shader 取經度時，接縫處的導數不連續會讓 mipmap 選錯，出現一條模糊的直線。改用連續的取樣座標加上 wrap，或手動提供導數。要邊繞鏡頭邊檢查，不能只看初始視角。
- 先放程式產生的漸層天空，圖載入後再淡入；圖載入失敗時畫面仍然可用。

## 3. 一天之中的變化

- 地平線色、天頂色、太陽光暈、霧色、曝光、月亮、星星，全部用連續的權重內插，不要在某個時間點直接切換。星星等天空暗下來之後才淡入；夜晚仍要保留足夠的環境光讓材質看得出來。
- **PMREM 不要每幀重建**，那會是整個場景最貴的部分。只在狀態有明顯改變時更新，或預先算好幾張再內插。換掉的 render target 要 dispose，但不要 dispose 仍在使用的貼圖。

## 4. 雲隙光（sun shafts／god rays）

這是螢幕空間的近似效果，不是體積散射。結構主要來自場景本身的遮擋（屋簷、樹葉），不是靠角度雜訊畫出來的。

做法：
1. 場景以線性 HDR 算繪。另外畫一張**天空遮罩**：天空白、不透明物體黑。樹葉的 alpha 剪裁與頂點擺動在遮罩 pass 裡也要一樣，否則葉子會變成實心方塊。用場景的 alpha 當遮罩只是最佳化，玻璃、粒子、AO 都可能破壞這個約定，要直接檢查遮罩。
2. 沿著太陽方向從鏡頭投影出一個點。太陽在鏡頭後方時不要用它的投影座標。`uv = ndc.xy * 0.5 + 0.5`，再注意貼圖的上下方向。
3. 每個光束緩衝的像素都往太陽 UV 走，取樣「天空遮罩 × 超過 HDR 門檻的天空亮度」，依衰減累加，最後除以權重總和，這樣改變取樣數不會改變亮度：

```text
step = (pixelUV - sunUV) * density / sampleCount
sampleUV = pixelUV - step * jitter
sum = 0; weightSum = 0; weight = 1
重複 sampleCount 次：
    sampleUV -= step
    若 sampleUV 在貼圖範圍內：
        energy = max(luminance(scene(sampleUV)) - threshold, 0)
        sum += min(energy, energyCap) * skyMask(sampleUV) * weight
    weightSum += weight
    weight *= decay
rays = sum / max(weightSum, epsilon)
```

4. 取樣點超出貼圖範圍就丟掉，不要夾在邊緣，否則會出現亮帶。太陽離開畫面越遠，效果就越淡；保留一點畫面外的邊距，讓剛好在畫面外的太陽仍有光束。
5. 在最後 tone mapping 之前，以加法疊回線性場景色。落在不透明前景（木頭、石頭）上的部分要大幅減弱，保留表面的對比。
   在本 plugin 裡，接進 `threejs-realtime-post` 的 `Post` 時，要放在 bloom 與調色之前。

起始數值：半解析度光束緩衝、24–48 個取樣；有色帶才增加。雜訊抖動可以減少色帶，但會閃爍。錄影或靜止畫面要用固定的雜訊（見 `webgl-deterministic-recording`）。貢獻為 0 時就跳過這個 pass。

畫面一片白，通常是強度太大或遮罩錯了，不是 bloom 不夠。

## 檢查

- 繞鏡頭一圈、上下看：沒有接縫、沒有被拉長的雲、看不到天空球的邊界，平移時天空沒有視差。
- 在主要視角下，太陽方向、陰影、光束、反射彼此一致。
- 屋頂和葉子的輪廓有切斷光束；葉子周圍沒有方形光暈。
- 轉身背對太陽時，光束消失，沒有反方向的假太陽，也沒有閃一下。
- 進到室內時表面仍有對比；跟太陽無關的自發光物體不會變成光源。
- 光束開與關各量一次影格時間。
