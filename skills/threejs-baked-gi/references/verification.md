# 驗證

## 1. 能量檢查（每次改 worker 都要跑）

`?test=furnace&bake=32`：一片平面，天空均勻 0.5，正上方太陽的貢獻 E = 0.5，打開 `bakeDirect`。
**`window.__gi.plane` 的 mean、min、max 都要是 1.000。**
不是的話，代表單位、MIS 權重或降噪有錯。範例實測是 1 / 1 / 1。

## 2. 數據

- `samples`、`tris`、`secs`：規模和速度。
- 各面的 mean／min／max（`floor`、`ceiling`、`back`）：
  - 任何一面的 max 遠大於 mean（例如 10 倍以上），通常代表有頂點跑到室外（看下方症狀表）。
  - min = 0 出現在角落是正常的，代表該處被遮住。

## 3. 固定鏡頭比較

| 比較 | 看什麼 |
|---|---|
| `?cam=room`（不烘焙，平光）vs `?bake=256&cam=room` | 烘焙要帶來窗邊亮、深處暗，以及家具的接觸陰影和色彩反彈 |
| `bake=64` vs `256` vs `1024`，加 `view=gi` | 收斂情形：256 跟 1024 應該幾乎一樣 |
| `view=gi` | 去掉材質顏色只看光，最容易看出斑點和漏光 |
| `cam=corner` | 牆角、牆腳：漏光或亮線 |

## 症狀對照（做範例時實際遇過）

| 症狀 | 原因 | 修法 |
|---|---|---|
| 整面牆斑斑駁駁，帶綠紫色塊 | spp 不夠：主要的間接光來自地板上一小塊陽光，靠 cosine 取樣很難打中 | 256 spp 加 smooth=2；或 `jobWeight` 給暗處多取樣 |
| 牆角、牆腳一顆顆的亮點，max 從 0.07 跳到 0.35 | 為了蓋接縫把牆往外延伸 1 cm，最外排頂點跑到牆外，看得到室外的太陽 | 被烘焙的平面精準對齊，外面另包黑殼 |
| 每條牆腳都有一條細白線，不烘焙時也有 | **即時**太陽陰影的 `normalBias = 0.02`，在接縫處漏光 | normalBias 0、bias −0.0002、4096 貼圖、frustum 收緊；剩下極淡的虛線屬於陰影貼圖解析度的極限 |
| 畫面幾乎全黑，只有窗戶亮 | 曝光照室外來設 | 曝光約 4.5（物理上室內本來就只有室外的 1/20） |
| worker 一直不回應，頁面卡住 | 從原專案複製時留著 `../core/gi.js` 的路徑而 404；或 worker 用了 bare import | 檢查 http log；worker 一律用 `cfg.imports` 的 URL |
| 套用後某些物件是平光 | 該網格 stale：名稱、順序或頂點數變了 | 看 `applyBake` 回傳的 stale 數；重新烘焙 |
| 光滑物件的反射對不上位置 | 沒有 box projection，或探針與房間 box 設錯 | `captureEnv` 傳入正確的房間 min／max |
| 反彈光整體偏亮且偏白 | 有貼圖的材質沒有給 `bake.albedo` | 給線性的平均反照率 |
| 紋路很深的法線貼圖在逆光坡面上發光 | 方向項的增益太大 | 原專案在布料材質把增益上限壓到 1.1（`detailPatch`） |
| 即時太陽在牆腳、牆角接縫漏出一排亮點（`normalBias` 已經是 0） | three.js 預設只把物體的**背面**畫進陰影貼圖。牆只有兩張薄面時，被畫進去的那一面和地板只差幾公釐，剛好被 shadow bias 吃掉；把 bias 加大反而會變成一整條亮線 | 在牆的兩張面之間放一個看不見的實心牆芯（`gi = false`、`bakeOccluder = false`），材質設 `shadowSide = THREE.FrontSide`。牆芯要離窗戶開口幾公釐，避免和窗洞側面重疊閃爍。做 `threejs-photoreal-interior` 的範本時實際遇到 |
